# CrossMambaNet

## Complementary Context Learning with Bidirectional Dual-View Mamba for Self-Supervised Network Traffic Classification

CrossMambaNet is a self-supervised network traffic classification framework based on dual-view masked representation learning and bidirectional Mamba state-space modeling.

This repository contains the implementation associated with the manuscript:

> **CrossMambaNet: Complementary Context Learning with Bidirectional Dual-View Mamba for Self-Supervised Network Traffic Classification**

---

## Overview

Deep learning has achieved strong performance in network traffic classification, but supervised approaches rely heavily on labeled traffic data.

CrossMambaNet investigates masked self-supervised traffic representation learning from a **context-diversity perspective**.

We distinguish two sources of contextual diversity:

- **Observation diversity**: generated by independently transformed observations of the same traffic sample.
- **Visibility diversity**: generated by independently sampled visible-token subsets.

The central question investigated in this work is:

> **Does the effect of visibility diversity depend on the observation condition under which it is introduced?**

CrossMambaNet combines independently transformed traffic observations with independently sampled masks and uses CrossMamba1D to aggregate the resulting contextual representations.

---

## Framework

The overall learning process can be summarized as:

```text
                    Traffic Sample
                         |
              +----------+----------+
              |                     |
        Transformation 1       Transformation 2
              |                     |
         Primary View          Auxiliary View
              |                     |
           Mask 1                  Mask 2
              |                     |
      Visible Token Set 1   Visible Token Set 2
              |                     |
              +----------+----------+
                         |
                   CrossMamba1D
                         |
            Bidirectional State-Space
                   Representation
                         |
                Primary-View Decoder
                         |
              Masked Reconstruction
```

During downstream fine-tuning, the masked-autoencoder decoder is removed and the pretrained encoder is used for traffic classification.

---

## CrossMamba1D

CrossMamba1D performs bidirectional state-space modeling for both contextual streams.

For each view, the token sequence is processed using:

- a forward Mamba branch;
- a backward Mamba branch.

The resulting bidirectional representations are subsequently aggregated in the latent space.

CrossMamba1D is therefore used primarily as a **context aggregation mechanism**, rather than simply as a larger replacement for a conventional Mamba encoder.

The architecture does not introduce explicit token-level cross-attention between the two views.

---

## Self-Supervised Pre-training

During masked self-supervised pre-training, two observations of the same stored traffic sample are generated independently.

For the joint-diversity configuration:

```text
Observation mode : Independent views
Mask mode        : Independent masks
Mask ratio       : 0.9
```

The reconstruction objective remains anchored to the masked regions of the **primary view**.

The auxiliary view contributes additional contextual information through the encoder representation.

The framework does **not** use:

- an auxiliary-view reconstruction target;
- an additional contrastive loss;
- an explicit cross-view consistency loss.

---

## Context-Diversity Configurations

The controlled experiments in the manuscript evaluate the following configurations:

| Variant | Configuration | CrossMamba1D | Observation Diversity | Visibility Diversity |
|---|---|---:|---:|---:|
| A | Single-view baseline | No | No | -- |
| B | Identical views + shared mask | Yes | No | No |
| E | Identical views + independent masks | Yes | No | Yes |
| D | Independent views + shared mask | Yes | Yes | No |
| C | Independent views + independent masks | Yes | Yes | Yes |

Variant **C** is referred to as the **joint-diversity configuration**.

## Input Representation

Each network traffic sample is represented using **1,600 bytes**.

Samples longer than the required input length are truncated, while shorter samples are padded to the fixed input size.

The traffic representation is treated as a single-channel byte image and subsequently flattened for token embedding.

The embedding configuration is:

```text
Input length     : 1600 bytes
Embedding stride : 4
Number of tokens : 400
```

---

## Dual-View Transformation

The dual-view transformation pipeline used in the reported experiments includes:

```text
Grayscale conversion
Tensor conversion
Random Erasing probability : 0.3
Random Erasing scale       : (0.02, 0.05)
Normalization mean         : 0.5
Normalization std          : 0.5
Gaussian noise std         : 0.01
```

The same stored traffic sample is retrieved twice and transformed independently to generate the two views.

## Model Configuration

### Encoder

```text
Encoder depth      : 4
Hidden dimension   : 256
Encoder block      : CrossMamba1D
Context streams    : 2
Scan directions    : Forward + Backward
```

### Decoder

```text
Decoder depth      : 2
Hidden dimension   : 128
Decoder backbone   : Mamba
```

The decoder is used only during self-supervised pre-training and is removed during downstream classification.

| Warm-up epochs | 5 |
| Layer-wise learning-rate decay | 0.75 |
| Label smoothing | 0.1 |
| Automatic mixed precision | Enabled |

## Controlled Context-Diversity Study

Results on CrossPlatform-Android:

| Variant | Accuracy (%) | Weighted F1 (%) | Macro-F1 (%) |
|---|---:|---:|---:|
| A | 98.25 ± 0.12 | 98.24 ± 0.12 | 98.02 ± 0.14 |
| B | 98.26 ± 0.09 | 98.26 ± 0.08 | 98.05 ± 0.06 |
| E | 97.92 ± 0.11 | 97.91 ± 0.12 | 97.68 ± 0.14 |
| D | 98.20 ± 0.09 | 98.19 ± 0.09 | 97.94 ± 0.12 |
| **C** | **98.38 ± 0.06** | **98.39 ± 0.06** | **98.16 ± 0.09** |

The results show a condition-dependent relationship between observation diversity and visibility diversity.

Under identical-view conditions:

```text
Shared mask -> Independent masks

Accuracy:
98.26% -> 97.92%
```

Independent masking therefore does not provide an independent additive improvement.

Under independent-view conditions:

```text
Shared mask -> Independent masks

Accuracy:
98.20% -> 98.38%

Weighted F1:
98.19% -> 98.39%

Macro-F1:
97.94% -> 98.16%
```

The benefit of visibility diversity therefore emerges when it is paired with observation diversity in the evaluated setting.

---

## ISCXVPN2016

Under independently transformed views, replacing shared masking with independent masking improves:

| Metric | Improvement |
|---|---:|
| Accuracy | +1.85 percentage points |
| Weighted F1 | +1.81 percentage points |
| Macro-F1 | +3.38 percentage points |

The accuracy improvement remains positive across all three evaluated seeds.

---

## Main Findings

The controlled experiments lead to four main observations:

1. **CrossMamba1D alone does not explain the final improvement.**
2. **Independent masking can decrease performance when the two branches receive identical observations.**
3. **Independent masking becomes beneficial when paired with independently transformed observations in the evaluated settings.**
4. **The effect of the joint-diversity configuration is benchmark dependent rather than universally superior.**

The main empirical design principle is therefore:

> **Observation diversity and visibility diversity should be jointly designed rather than independently stacked.**
